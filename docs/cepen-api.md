# API своего цепня — инструкция для агента приложения

## Адрес и назначение

Базовый адрес: **https://94.183.184.65**
Префикс версии: **/api/v1**. Только HTTPS, обычная проверка TLS-сертификата должна оставаться включённой. Серверный IP статичен; HTTPS `/api/health` проверен с валидацией сертификата.

API читает своего цепня в выбранном групповом чате. Доступа к SQLite и выполнения SQL в приложении нет. API не позволяет чесать, переименовывать, кормить, менять скин или генерировать аватарку. Схема существующей БД не менялась.

## Полный сценарий подключения

1. Открыть личный чат **https://t.me/udb_flood_bot** и отправить `/auth`.
2. Пользователь переносит четырёхзначный код в приложение.
3. Приложение вызывает `POST /api/v1/auth/code` и получает Bearer-токен.
4. С этим токеном вызвать `GET /api/v1/chats`, показать список чатов, выбрать `chat_id`.
5. Вызвать `GET /api/v1/cepen?chat_id=...`.
6. Если `avatar_url` не null, загрузить изображение по этому URL **с тем же Authorization**.

`chat_id` передаётся явно: выбор чата или посещаемого игрока в веб-версии на этот API не влияет. Telegram user_id владелец не вводит — сервер определяет его из токена. Чаты берутся из зарегистрированных аккаунтов пользователя в БД бота, а не из отдельной проверки членства Telegram на каждый запрос. Отсутствие цепня не мешает входу.

## 1. Обмен кода на токен

```http
POST /api/v1/auth/code
Content-Type: application/json

{"code":"0007"}
```

Код — **строка ровно из четырёх цифр ASCII**, включая начальные нули. Передавать его в URL не нужно. Действует до двух часов с выдачи; код одноразовый и общий с существующим веб-входом. Если он уже использован в вебе или приложении, получить новый через `/auth`.

Успех, HTTP 200:

```json
{
  "access_token": "<opaque-token>",
  "token_type": "Bearer",
  "expires_in": 2592000,
  "expires_at": "2026-11-16T12:00:00+00:00",
  "scope": "cepen:read"
}
```

Дата приведена как пример. `expires_in` — секунды, срок 30 суток; `expires_at` — ISO8601 UTC. Срок проверяется сервером. Токен — непрозрачная строка, **не JWT**: не нужно разбирать его или пересобирать. Он не даёт доступ к административным API, веб-сессии или AI-worker.

Сохранять токен в защищённом хранилище приложения. При выходе удалять локально. В v1 нет refresh-token и отдельного отзыва токена: при истечении нужен новый код; ротация серверного секрета инвалидирует выданные токены. Cookie браузера для этих методов не используется.

Каждый защищённый запрос:

```http
Authorization: Bearer <access_token>
```

На новом endpoint входа установлен предел **5 попыток/IP/60 секунд**, **30 попыток/процесс/60 секунд**, включая удачные. При превышении HTTP 429 и `Retry-After: 60`. Состояние этого ограничителя хранится в памяти процесса и сбрасывается при перезапуске; сам код и одноразовое использование остаются в БД. Неверный JSON/формат возвращает 422 до выполнения входа. Не перебирать коды и не повторять вход фоновым циклом.

## 2. Список доступных чатов

```http
GET /api/v1/chats
Authorization: Bearer <access_token>
```

HTTP 200:

```json
{
  "chats": [
    {"chat_id": -1000000000001, "chat_name": "Пример игрового чата"}
  ]
}
```

Здесь только групповые чаты (`chat_id < 0`), в которых пользователь зарегистрирован в БД бота. Список может быть пустым. Балансы, профили и данные других участников не возвращаются. ID — знаковое 64-битное целое; не использовать 32-битный тип.

## 3. Данные цепня

```http
GET /api/v1/cepen?chat_id=-1000000000001
Authorization: Bearer <access_token>
```

HTTP 200, пример:

```json
{
  "schema_version": 1,
  "user_id": 123456789,
  "owner_name": "Пример владельца",
  "chat_id": -1000000000001,
  "chat_name": "Пример игрового чата",
  "mechanic_enabled": true,
  "has_cepen": true,
  "name": "Пушок",
  "length_cm": 42.25,
  "appearance_level": 3,
  "profession_id": "designer",
  "profession_title": "Цепень-дизайнер",
  "profession_selected": true,
  "avatar_url": "/api/v1/cepen/avatar?chat_id=-1000000000001&v=example-version",
  "mood": "счастлив"
}
```

| Поле | Тип | Значение |
|---|---|---|
| `schema_version` | integer | Сейчас 1. |
| `user_id` | integer | Telegram ID авторизованного владельца. |
| `owner_name` | string | Сохранённое имя владельца, может быть пустым. Обычный текст, не HTML. |
| `chat_id` | integer | Выбранный групповой чат. |
| `chat_name` | string | Название из общего кеша чатов; при недоступном названии — существующая резервная подпись. |
| `mechanic_enabled` | boolean | Включена ли механика цепней в чате. |
| `has_cepen` | boolean | Есть ли сохранённый цепень: длина больше нуля. |
| `name` | string/null | Имя цепня, null если не задано или цепня нет. |
| `length_cm` | number | Длина в сантиметрах; 0 если цепня нет. |
| `appearance_level` | integer/null | Ступень изображения 1–10, null если цепня нет. Это не самостоятельная игровая характеристика опыта. |
| `profession_id` | string/null | Код выбранной профессии; null если не выбрана или цепня нет. |
| `profession_title` | string/null | Название профессии; «Без профессии» для существующего цепня без выбора; null если цепня нет. |
| `profession_selected` | boolean | Есть ли действующий выбор профессии. |
| `avatar_url` | string/null | Относительный защищённый URL актуального изображения; null если цепня нет. |
| `mood` | string/null | `подавлен`, `удовлетворён`, `счастлив`; null если цепня нет. |

Настроение считается по почёсываниям за текущую календарную дату **Asia/Yekaterinburg**: 0 → подавлен, 1–9 → удовлетворён, от 10 → счастлив. Оно использует ту же функцию, что голосовые реплики, и не меняет изображение лица.

Уровни изображения: до 15/30/60/120/200/300/400/500/700 см включительно — уровни 1–9; больше 700 — уровень 10.

Коды профессий: `designer`, `programmer`, `doctor`, `teacher`, `chef`, `scientist`, `plumber`, `artist`, `detective`, `gamer`. Для подписи использовать `profession_title`, не конструировать её по коду.

Если цепня нет: ответ всё равно 200; `has_cepen=false`, `length_cm=0`, `profession_selected=false`, поля имени/уровня/профессии/аватарки/настроения — null. Данные владельца и чата остаются.

Если механика выключена: `mechanic_enabled=false`; сохранённый цепень не удаляется, поэтому `has_cepen` может оставаться true. Приложение должно показать отключённую механику, не изображать исчезновение питомца.

Чужой `chat_id` даёт 403. Параметра выбора чужого `user_id` нет; передача такого query-параметра не меняет владельца.

## 4. Картинка

Использовать **полный относительный `avatar_url` из ответа**, присоединив к базовому адресу через URL-resolve, и передать Authorization. Не добавлять токен к URL.

```http
GET /api/v1/cepen/avatar?chat_id=-1000000000001&v=example-version
Authorization: Bearer <access_token>
```

Успех: HTTP 200, тело — исходные байты изображения. `Content-Type` соответствует содержимому: `image/png`, `image/jpeg` или `image/webp`. Расширение файла на сервере не определяет формат.

Выбор совпадает с настройками бота: доступный включённый ИИ-кеш подходящего размера/скина и текущей ревизии, иначе обычная мультяшная аватарка. Старая, отключённая или пропавшая ИИ-картинка не используется. API не запускает новую ИИ-генерацию и не расходует её квоту. Обычная картинка при необходимости собирается существующим рендерером и кешируется на сервере.

`v` — непрозрачная версия для клиентского кеша, не ключ доступа и не путь к файлу. Она меняется при смене актуального изображения. Запрос картинки всегда проверяет доступ и выбирает текущее изображение. Кеш только приватный (`private, max-age=300`, `Vary: Authorization`); при изменении `avatar_url` обновить картинку. При отсутствии цепня — 404.

HTML `<img src>` не отправляет Bearer автоматически: браузерному клиенту нужен fetch с заголовком и Blob URL; мобильной библиотеке изображений — поддержка headers. URL не предназначен для публичного размещения или пересылки.

## Ошибки

Прикладные ошибки:

```json
{"detail":{"code":"invalid_token","message":"Token invalid or expired"}}
```

| HTTP | `detail.code` | Действие клиента |
|---|---|---|
| 401 | `invalid_code` | Неверный/истёкший/использованный код: попросить новый `/auth`. |
| 401 | `invalid_token` | Нет/испорчен/истёк токен: повторить вход. |
| 403 | `chat_forbidden` | Обновить список чатов; этот чат недоступен владельцу. |
| 404 | `no_cepen` | Только для картинки: обновить состояние питомца. |
| 409 | `ambiguous_code` | Получить новый `/auth` код. |
| 422 | массив `detail` FastAPI | Исправить JSON, формат кода или `chat_id`; не повторять тот же запрос циклом. |
| 429 | `rate_limited` | Выждать `Retry-After`. |
| 503 | `auth_unavailable` | Серверная настройка авторизации недоступна. |
| 503 | `avatar_unavailable` | Обычная аватарка временно недоступна; повторить позже. |

Сетевые ошибки/5xx повторять с ограниченной задержкой, например 2/5/15 секунд; 401 автоматически бесконечно не повторять. JSON-ответы успешного входа/состояния/списка чатов имеют `Cache-Control: no-store`.

## Пример Python

```python
import requests
from urllib.parse import urljoin

BASE = "https://94.183.184.65"
http = requests.Session()
login = http.post(f"{BASE}/api/v1/auth/code",
                  json={"code": input("Код из /auth: ").strip()}, timeout=15)
login.raise_for_status()
http.headers["Authorization"] = "Bearer " + login.json()["access_token"]

chats = http.get(f"{BASE}/api/v1/chats", timeout=15)
chats.raise_for_status()
accounts = chats.json()["chats"]
if not accounts:
    raise RuntimeError("Нет доступных игровых чатов")
# В приложении здесь дать пользователю выбрать чат.
chat_id = accounts[0]["chat_id"]
response = http.get(f"{BASE}/api/v1/cepen", params={"chat_id": chat_id}, timeout=15)
response.raise_for_status()
pet = response.json()
if pet["avatar_url"]:
    image = http.get(urljoin(BASE, pet["avatar_url"]), timeout=30)
    image.raise_for_status()
    # image.content — изображение; передать декодеру изображений приложения.
```

## Ограничения интеграции

API рассчитан на прямые HTTPS-запросы нативного приложения или его backend. CORS для произвольных сторонних доменов не включён. Для отдельного браузерного frontend нужен согласованный origin и настройка CORS либо свой backend-прокси; нельзя обходить это отключением TLS.

Для состояния достаточно обновления при открытии/возврате экрана и примерно раз в 60 секунд, пока экран активен. Картинку скачивать при изменении URL или отсутствии локального кеша. Постоянный частый опрос и обращения к ИИ для чтения не нужны.

Связанные исходники: `web/cepen_api.py`, регистрация в `web/server.py`, общий mood в `cepen_messages.py`, проверка ИИ-кеша в `cepen_ai_avatar.py`. Регрессионные проверки: `tests/test_cepen_api.py`.
