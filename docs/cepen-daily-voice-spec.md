# Цепень: ежедневная реплика хосту

## Цель

Сделать цепня активным персонажем чата: каждый день он обращается к своему хосту одной случайной репликой из согласованного списка. Реплика должна появляться в непредсказуемое время и не дублироваться после перезапуска бота.

## Текущее и ожидаемое поведение

- Сейчас цепень пишет только при заражении, лечении и вечернем росте.
- После изменения каждому пользователю с цепнем один раз за серверный календарный день назначается случайная реплика и случайное время с 10:00:00 до 22:59:59 по локальному времени сервера.
- Реплики загружаются из `docs/cepen-host-phrases.md`; нумерация может иметь пропуски, в отправляемый текст номер и заголовок раздела не попадают.
- `{nickname}` заменяется безопасным Telegram-упоминанием хоста. Следующей строкой добавляется подпись `– твой цепень ❤️`.
- Если механика цепня выключена в чате или пользователь вылечен до назначенного времени, сообщение не отправляется. При включении механики или заражении внутри окна назначается время в оставшейся части окна.
- Неуспешная отправка остаётся в очереди для повторной попытки в тот же день. После 23:00 просроченные сообщения не отправляются.

## Критерии готовности

- [x] Для каждого заражённого в групповом чате создаётся не более одного задания на дату.
- [x] Назначенное время попадает в интервал 10:00:00–22:59:59 серверного времени.
- [x] Успешно отправленная реплика не повторяется после перезапуска цикла.
- [x] Сообщение содержит упоминание хоста и отдельную строку `– твой цепень ❤️`.
- [x] Выключенная механика и вылеченный пользователь не получают реплику.
- [x] Список реплик читается из отредактированного Markdown-файла без требования непрерывной нумерации.

## Контракты и данные

Новая таблица `cepen_daily_messages`:

- `message_date` — серверная дата задания `YYYY-MM-DD`;
- `chat_id`, `user_id` — получатель в чате;
- `scheduled_at` — назначенное серверное время `YYYY-MM-DD HH:MM:SS`;
- `phrase` — зафиксированный текст выбранной реплики с `{nickname}`;
- `sent_at` — фактическое серверное время успешной отправки или `NULL`.

Первичный ключ `(message_date, chat_id, user_id)` делает ежедневное назначение идемпотентным. Миграция создаёт таблицу через `CREATE TABLE IF NOT EXISTS` и безопасна для существующей базы.

## План реализации

1. Добавить идемпотентную таблицу очереди в общую инициализацию БД.
2. В `cepen.py` добавить чтение Markdown, планирование, выбор просроченных заданий и подтверждение успешной отправки.
3. Запустить отдельный фоновый цикл из `main.py`.
4. Покрыть парсинг, интервал, однократность, подпись, выключение и лечение тестами.
