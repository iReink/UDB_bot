## Цель

Исключить ложные вторичные заражения, когда пользователь вызывает команду бота в контексте ответа, и перестать уведомлять доктора через активный Telegram-тег при каждом заражении.

## Текущее и ожидаемое поведение

- Сейчас: middleware после обработки любого сообщения проверяет `reply_to_message`. Команды, включая `/shop`, не отличаются от обычных ответов и при наличии reply-контекста могут заразить отправителя. Инструкция под заражением содержит `@jprgprh`.
- После изменения: сообщения с Telegram-сущностью `bot_command` и текстом команды не участвуют в заражении через ответ. Обычный ответ заражённому сохраняет настроенный вторичный шанс. В инструкции остаётся информация об официальном докторе без активного тега.
- Проверка кандидата на заражение фиксирует источник до запуска обработчика команды, чтобы результат не зависел от работы обработчика.

## Критерии готовности

- [x] `/shop`, отправленный с reply-контекстом заражённого пользователя, не запускает проверку вторичного заражения.
- [x] Обычный текстовый ответ заражённому пользователю по-прежнему запускает проверку.
- [x] Ответ самому себе и ответ сообщению бота не запускают проверку.
- [x] В первичных и вторичных уведомлениях отсутствует `@jprgprh`.

## Контракты и данные

Схема БД и сохранённые состояния не меняются.

## План реализации

1. Вынести определение допустимого источника ответа в чистую функцию `cepen.py`.
2. Использовать снимок источника в middleware и отфильтровать команды.
3. Изменить общую инструкцию заражения и добавить регрессионные тесты.

## Итог после реализации

- Что фактически сделано и какие решения отличаются от плана: добавлен единый фильтр допустимого ответа; источник фиксируется до обработчика, Telegram-команды распознаются как по entity, так и по тексту на случай неполного объекта сообщения. Общая инструкция заражения больше не содержит username доктора.
- Результаты проверок: целевой `test_cepen.py` — 21 тест; полный `python scripts/check.py` — синтаксис 56/56 и 52 теста. Все проверки прошли.
- Известные ограничения: бот не сохранял исходные Telegram update, поэтому историческое значение `reply_to_message` для конкретного сообщения Анны восстановить из серверной БД невозможно. Код подтверждает единственный путь такого уведомления: Telegram update команды содержал ссылку на сообщение заражённого пользователя.
