# Видимость цепня в личных сценариях

## Цель

Не показывать здоровому участнику действия и статистику, которые относятся только к его цепню.

## Ожидаемое поведение

- В `/shop` товар лечения за 50 сит виден только вызывающему с цепнем, если механика включена в чате. Это действует и при открытии магазина командой, и при возвращении в меню кнопкой.
- Во `/flood` строка с длиной цепня и ссылкой на `/cepen` появляется только у заражённого, если механика включена.
- Старая кнопка покупки лечения по-прежнему проверяет состояние при нажатии: у здорового пользователя ситы не списываются.
- `/cepen` по прямому запросу здорового пользователя сообщает об отсутствии цепня. Общая справка `/help` остаётся доступной всем.

## Критерии готовности

- [x] Здоровый участник не видит лечение в обоих меню магазина и строку цепня во `/flood`.
- [x] Заражённый видит лечение и длину цепня при включённой механике.
- [x] При выключенной механике оба элемента скрыты независимо от сохранённой длины.
- [x] Проверка кода проекта проходит через `scripts/check.py`.

## Контракты и данные

Используются существующие `users.cepen` и `settings.enable_cepen`; миграция не нужна.

## План

Передать ID вызывающего при построении клавиатуры магазина, добавить проверку положительной длины во `/flood`, проверить обе ветки и выполнить общие проверки.

## Результат проверки

Локально проверены три состояния (здоровый, заражённый, механика выключена) на построении клавиатуры и тексте `/flood`. `scripts/check.py`: синтаксис 56/56, 39 тестов.
