## Цель

Гарантировать, что результат дуэли одновременно фиксирует прибавку победителю и вычет проигравшему, а сообщение показывает состояние после одной операции.

## Текущее и ожидаемое поведение

- Сейчас: обработчик дуэли вызывает два независимых изменения длины. Между ними другой обработчик или фоновая механика может увидеть промежуточное состояние; при сбое второй операции результат может быть частично применён.
- После изменения: обе длины меняются внутри одной транзакции SQLite. Сообщение о победе получает оба значения из этой же атомарной операции.
- Повторный вызов с теми же параметрами не должен оставлять только одну сторону изменённой.

## Критерии готовности

- [x] Победитель получает ставку, проигравший теряет ставку в одной транзакции.
- [x] Возвращаемые значения соответствуют фактически сохранённым длинам.
- [x] Нельзя применить результат к одному и тому же пользователю с двух сторон.

## Контракты и данные

Схема базы не меняется. Добавляется внутренняя функция `apply_duel_result` в `dick.py`.

## План реализации

1. Объединить два изменения длины в одну транзакцию.
2. Перевести обработчик дуэли на новый путь.
3. Проверить синтаксис, тесты и ручной сценарий на копии базы.

## Итог после реализации

- Что фактически сделано: добавлена `apply_duel_result`, которая фиксирует обе стороны дуэли через одну транзакцию; обработчик `dick:duel` использует возвращённые значения для сообщения.
- Результаты проверок: синтаксис и полный набор тестов выполнены; ручная проверка на копии базы подтвердила переход `121 → 181` при ставке 60.
- Известные ограничения: уже отправленные сообщения и уже завершённые дуэли не пересчитываются.
