# Дейлики, календарь и фото

## Создание и участие в дейлике {#events}
/daily создаёт встречу с названием, описанием, датой/временем, ссылкой и признаком машин. daily_events хранит событие; daily_participants — участие и водителя. Можно присоединиться, отказаться, указать машину, редактировать свои события; права дополнительно проверяются сервером. Число автомобилей не равно числу мест, а отметка водитель отличается от обычного участника. Поиск фильтрует название, диапазон дат, собственные встречи и наличие фото. Встреча в БД и её календарная копия — разные записи, синхронизация применяется к настроенному чату.

## Фотоальбомы и обработка {#photos}
Фотографии и видео из настроенной темы ставятся в очередь пакетами и связываются с подходящим дейликом; при неоднозначности нужен выбор. Файл ограничен 20 MB, свободное место проверяется с порогом 512 MB. Медиа хранится отдельно от SQLite; таблицы описывают пакеты, файлы и состояния. Конвертация выполняется отдельным процессом, поэтому появление превью не мгновенно. Сервер проверяет права удаления и принадлежность чату. Отсутствие альбома не доказывает отсутствие встречи.


## История встречи по фотографиям {#story}
Через 24 часа после назначенного времени дейлика бот пишет тёплую юмористическую историю по сохранённым фотографиям. Если фото были доступны к сроку, история публикуется в чат и веб-альбом. Встречи без фото не получают сообщения. Старые встречи при первом включении и впервые загруженные поздние фото получают рассказ только в альбоме, без уведомления чата. Готовая история не переписывается при новых фотографиях.
Кадры сортируются по EXIF-времени съёмки, если оно сохранилось; иначе — по отправке и устойчивым ID. Сжатие Telegram часто удаляет теги, поэтому это не гарантированная хронология. Большие подборки проходят порциями по десять и объединяются в один рассказ. При лимитах обработка продолжается после восстановления; точные факты вне кадров не придумываются. Отключение ИИ действует; остальные режимы используют внешний API для фото. Неизвестная доставка не вызывает повторную публикацию, но готовая история остаётся в альбоме.
