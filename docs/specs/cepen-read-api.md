# API чтения своего цепня

## Цель и контракт
Стороннее приложение получает только основные сведения, актуальную аватарку и mood. Выбор чата обязателен; владелец берётся из авторизации. POST /api/v1/auth/code обменивает существующий одноразовый /auth код на отдельный read-only Bearer-токен (30 дней, exp проверяется сервером, HMAC с разделением ключей от веб-cookie). GET /api/v1/chats перечисляет собственные групповые чаты. GET /api/v1/cepen?chat_id= и GET /api/v1/cepen/avatar?chat_id= проверяют свою пару user/chat на каждом запросе, не учитывая выбранного гостя веб-сессии. Никаких операций записи цепня.

## Поведение
Основные сведения все согласованные: user_id, owner_name, chat_id, chat_name, mechanic_enabled, has_cepen, name, length_cm, appearance_level, profession_id/title/selected; плюс avatar_url и mood. Нет цепня — 200, has_cepen=false, length_cm=0, nullable поля=null. Отключённая механика отдельно обозначается флагом, существующие данные сохраняются. Изображение: доступный актуальный включённый ИИ-кеш, иначе обычное; генерацию ИИ не запускать. Mood вычисляется общей функцией с репликами цепня по дате Екатеринбурга.

## Данные и безопасность
Новых таблиц нет. Читаются users/settings/cepen_scratches/cepen_ai_avatars; /auth использует существующие web_auth_codes. Коды и токены не логируются. Не раскрываются пути файлов, профиль, переписка, баланс или служебные prompts. Ограничение нового входа: 5 попыток/IP/минуту, 30 на процесс/минуту, 429 с Retry-After; ограниченное хранилище в памяти. Cookie веба не заменяет Bearer; токен API не даёт прав веба/AI-worker. Доступ по существующему проверенному HTTPS, без CORS для произвольных сайтов.

## Проверки
Временная БД и HTTP TestClient: вход/повтор кода/срок/подпись/чужой чат/подмена user_id, отсутствие цепня, выключенная механика, профессия, mood на границах, ИИ/обычная аватарка/пропавший файл/отключённый кеш/авторизация медиа, отсутствие записи и вызовов ИИ при чтении, лимиты авторизации. Полный scripts/check.py; после развёртывания искусственная подписанная сессия для read-only проверки без расходования кода реального пользователя. Обновить публичную справку, архитектуру, инструкции и манифест. Дополнительный бэкап не создавать.
