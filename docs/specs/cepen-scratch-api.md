# Почёсывание своего цепня через API

## Цель и поведение
POST /api/v1/cepen/scratch принимает chat_id, count (целое 1–50), request_id (UUID). Владелец определяется только Bearer-токеном с отдельным правом cepen:scratch. Старые read-токены не получают права записи; новый /auth выдаёт оба права. Общие Telegram/API лимиты: 5 от хозяина, 50 всего за дату Екатеринбурга. Принимается доступная часть количества, остаток не переносится. Награды проходят общую функцию scratch и ledger с налогами/взысканием. Telegram-сообщения не отправляются.

## Контракты и данные
Ответ 200: request_id, requested_count, accepted_count, rejected_count, reason (null/user_limit/worm_limit), scratch_date, total_count, owner_count, owner_remaining, total_remaining, reward_sits (чистая прибавка баланса), mood. Количество больше 50/нецелое/неположительное — 422; чужой чат 403, нет цепня 404, выключенная механика 409. Повтор того же UUID в паре чат/хозяин возвращает сохранённый ответ, даже после смены даты; другое count с тем же UUID — 409 idempotency_conflict. Квитанция и все начисления фиксируются одной BEGIN IMMEDIATE транзакцией; ошибка откатывает всю пачку. Отказ до записи квитанции допускает повтор.
Новая служебная таблица cepen_api_scratch_requests; повторяемое создание при initialize_db, без DDL на запросах. Миграция на старой временной БД, без внепланового бэкапа.
