# Гибкие личные пожелания

## Цель
Свободные просьбы о форме общения сохраняются, включая префиксы, эмодзи и срок действия. Подтверждение появляется только после записи, не из обычной модели ответа.

## Поведение
Модель извлекает нормализованные пункты, конфликты и срок из текущего адресованного сообщения; цитаты, пересылки и чужие настройки не исполняются. Независимые пожелания накапливаются. Время — Asia/Yekaterinburg, без года ближайшая будущая дата. Истёкшие пункты исключаются кодом. При отказе API или неправильном JSON запись не меняется, бот сообщает об ошибке. Никаких дополнительных бэкапов.

## Данные
Совместимая миграция ai_user_preferences: nullable expires_at (UTC ISO). Старые поля продолжают читаться. Новые custom:slug содержат короткий нормализованный текст, не исходное сообщение. Транзакция проверяет изменение снимка, подтверждения идемпотентны. API через существующие квоты и аудит, вне SQLite-транзакции и event loop.

## Проверки
Два пользовательских примера, сроки/граница, независимые пункты/конфликт/отмена, старые строки/повтор миграции, безопасность/цитаты, невалидный JSON/API, конкурентные изменения, полный scripts/check.py. Искусственная реальная API-проба без Telegram и пользовательских записей.

## Реализовано и проверено
Модель нормализует свободные пожелания; сроки проверяются кодом и не передаются
модели финального ответа. Активные пожелания расположены после обычной персоны и
явно выше стандартного ограничения эмодзи. Сохранение подтверждает обработчик БД.
Реальная API-проба на искусственных данных: эмодзи, условный срок, отмена только
эмодзи и отказ изменения баланса. Временная SQLite подтвердила сохранение двух
пунктов, просмотр и исключение префикса на границе срока. Финальная модель выдала
ответ с буквальным префиксом и несколькими эмодзи. Публикаций в Telegram и
изменений пожеланий реальных пользователей не было.
