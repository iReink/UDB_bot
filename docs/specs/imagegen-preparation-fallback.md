# Подготовка imagegen без бесконечного ожидания

## Цель и поведение
Задача изображения не должна бесконечно обходить текстовые модели вместо вызова генератора. Один проход подготовки; при недоступности всех моделей или непригодном ответе используем исходный запрос и все реальные референсы. Повтор загрузки фото ограничен двумя попытками после первой, с сохранённым счётчиком. Ошибки генератора сохраняют существующие правила.
Ответ на фотографию с новыми фото включает исходный кадр первым, затем текущие кадры по Telegram message_id. Все кадры участвуют в подтверждении первых четырёх. Старые заявки без потерянной ссылки нельзя достроить догадкой.

## Контракт
ai_imagegen_batches.reply_photos_json TEXT NOT NULL DEFAULT '[]': ссылки на фотографии из reply в том же чате, без байтов медиа. Повторяемая миграция старых баз; ai_imagegen_inputs остаётся таблицей текущих сообщений. photos() объединяет ссылки и ввод. Счётчик сетевых повторов — существующий ai_tasks.transport_attempt.

## Проверки
Отказ подготовки → единственный вызов генератора с исходным запросом; успешная подготовка сохраняется; ошибка загрузки ограничена; повтор update и перезапуск не дублируют референс; reply+альбом из четырёх требует выбора; другая группа исключена; старая схема мигрирует повторно.

## Итог после реализации
Реализованы единичный проход подготовки (таймаут вызова 20 секунд), fallback на исходный запрос, сохранение референса reply отдельно от альбома, общий порядок и подтверждение, повторяемая миграция и два сетевых повтора загрузки. Сбой аудита подготовки не блокирует генерацию. scripts/check.py: 322 теста успешно; на VPS пять сценариев с имитацией внешнего API успешно, миграция подтверждена, веб HTTP 200, службы активны. Заявка 10665 остановлена как неполная: исходный референс в старой записи отсутствует. Живой повтор генерации с этой фотографией не запускался, требуется новое сообщение пользователя. Использована ранее проверенная суточная внешняя копия, дополнительных бэкапов нет.
