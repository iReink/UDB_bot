# Надёжное удаление пожеланий

## Проблема и поведение
Точечные удаления попадали на HTTP 503/ReadTimeout двух Google-моделей. Полная очистка зависела от обязательного слова «мои», а корректный JSON clear с перечислением существующих remove отклонялся валидатором.

## Изменения
Полная очистка в формулировках «очисти пожелания», «удали пожелания», «удали все инструкции и пожелания по общению со мной» выполняется локально, без модели, только для автора/чата. Системные инструкции, цитаты и пожелания других людей не затрагиваются. Clear допускает избыточное перечисление всех действующих удаляемых ключей при пустом set; неизвестные ключи, неполный список remove и set с clear остаются ошибкой, чтобы точечная отмена не превратилась в полную очистку.
Для семантического изменения/точечного удаления: Flash Lite 3.5, 3.1, затем существующая Groq GPT-OSS-120B. Общий дедлайн 16 секунд: Google до 4 секунд на попытку, остаток Groq; без повторного круга и активного ожидания. Общие квоты и аудит сохраняются. Причины недоступности/некорректного ответа различаются в безопасной диагностике и сообщении.

## Проверка
Все формулировки со скриншота, очистка при выключенных API, clear с redundant remove, отказ при неизвестных ключах, запасная модель после Google 503/timeout, снимки/идемпотентность/изоляция. Временная БД, без реальных пожеланий для тестов. Полный scripts/check.py; публикация через sync_mechanics, без дополнительного бэкапа. Схема БД неизменна.
