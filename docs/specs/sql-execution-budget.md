# Ограничение выполнения пользовательского SQL

## Цель
Запрос модели с рекурсивным CTE или дорогим соединением не должен удерживать основной воркер бесконечно. Сохранить существующие проверки чтения, изоляцию чата, ограничение строк, повторы исправления SQL и защиту доставки.

## Поведение
Общий execute_readonly_sql прерывает выполнение и выборку после 5 секунд монотонного времени либо 20 миллионов VM-инструкций SQLite. Проверка каждые 1000 инструкций; таймаут ожидания блокировки БД не больше бюджета. При превышении возвращается ошибка для существующего исправления SQL/окончательного отказа, очередь продолжает работу. Не выбирать произвольные результаты незавершённого запроса. Схема не меняется.

## Проверки
На временной базе: обычный SELECT, LIMIT выборки, бесконечная рекурсия, временной бюджет, операция записи, сложный первый запрос и успешный следующий. После полного check.py публиковать ai_tasks и документацию; перезапуск веба остановит старый SQL. Восстановить только диагностированную задачу 10801 до этапа Telegram, сохранив идемпотентную квитанцию старой попытки и число исправлений. Остальные задачи не пересоздавать.
