# Следующие этапы сокращения техдолга

Эта карта основана на коде на 19 сентября 2026 года. Каждое выделение выполняется отдельным изменением с тестом поведения до переноса и полным прогоном `python scripts/check.py` после него. Не совмещай его с новой функцией.

1. **Зависимости и чистая установка.** Сверить пакеты локального окружения и VPS, добавить единый перечень зависимостей бота и тестов, затем проверить создание нового окружения. Сейчас `requirements-web.txt` и `requirements-photos.txt` покрывают только свои части, а полный тестовый запуск зависит от установленных вручную пакетов.
2. **Инициализация схемы.** Собрать список таблиц и мест `ensure_*` из `db.py`, `ai_tasks.py`, `web/server.py` и профильных модулей. Проверить повторный запуск миграций на копии старой БД. После этого постепенно вынести миграции из импорта `db.py` в явный запуск.
3. **Веб-маршруты.** Разделять `web/server.py` по одной области за раз: авторизация, дейлики, баланс/покупки, AI API. Перед переносом сохранить тесты HTTP-контрактов и транзакций; не менять URL и формат ответов одновременно с переносом.
4. **Telegram-обработчики.** Аналогично выделять из `main.py` законченные группы команд, сохраняя регистрацию обработчиков и фоновых задач. Начинать с группы, у которой есть тесты без доступа к Telegram API.
5. **Отдельные хранилища.** Проверить, где используется `stats.json` и `masturbate.db`, затем документировать владельца данных, резервирование и миграции. Не менять формат хранения без плана восстановления.

Причина такого порядка: в текущем рабочем дереве уже есть значительные незавершённые изменения в `main.py`, `web/server.py` и `db.py`. Сначала нужна повторяемая проверка и контрактные тесты; перенос больших блоков поверх этих изменений усложнит поиск регрессии.
